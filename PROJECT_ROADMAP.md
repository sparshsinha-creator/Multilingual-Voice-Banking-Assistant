# Project Roadmap

## Where this stands today

Phases 1–7 are all built and independently runnable. The pipeline goes from
a raw mic recording through Whisper ASR, automatic Hindi/Kannada/Tamil/
English language detection and translation, a FAISS-retrieved RAG answer
grounded in a 27-item fintech FAQ dataset generated by a Groq-hosted LLM,
and a LangGraph agent that routes each question to that RAG node or to a
rules-engine tool for Atal Pension Yojana eligibility — then back out
through gTTS as spoken audio. Phase 6 wraps the full pipeline in a Gradio
browser UI for live demos, and Phase 7 is a standalone React + Vite +
Tailwind landing page for sharing the project outside a terminal. Nothing
here is deployed; everything runs locally against a Groq API key.

## Known limitations

These are intentional simplifications for a portfolio build, not oversights:

- No authentication or multi-user sessions — single local process, single user.
- No production deployment — Phases 1–6 only run locally; there's no hosted backend.
- Language coverage is Hindi, Kannada, Tamil, and English, not all 22 scheduled Indian languages.
- The Atal Pension Yojana eligibility tool parses fixed values out of a single question rather than running a real multi-turn slot-filling conversation (e.g. it won't ask "what's your age?" if you don't mention it).

## Near-term roadmap (next 1–2 weeks, pre-interview polish)

| Item | Why it matters | Effort |
|---|---|---|
| Record real test utterances per language and measure word error rate | Right now ASR accuracy is untested beyond casual use — WER numbers are the first thing anyone technical will ask for | M |
| Turn the eligibility tool into a real multi-turn slot-filling flow | Fixed single-pass parsing is the weakest part of the agent demo; a real slot-filling loop is a much stronger signal of agentic design skill | M |
| Add a guardrail check that blocks any RAG answer not traceable to a retrieved FAQ chunk | Prevents the LLM from confidently answering outside the grounded context — a basic but necessary safety property for a regulatory-info assistant | S |
| Deploy the Phase 7 landing page live (Vercel/Netlify) | A live link is far more shareable than "clone and run" for a LinkedIn post or interview follow-up | S |
| Record a short demo video | Most reviewers won't set up a mic/venv locally — a video is the only way most people will actually see it work | S |

## Mid-term roadmap (if extended past the interview)

| Item | Why it matters | Effort |
|---|---|---|
| Swap Whisper/gTTS/deep-translator for Sarvam's APIs (Saaras for ASR, Bulbul for TTS, Sarvam-Translate) behind the same interfaces | Proves the architecture was built provider-agnostic from the start — the LangGraph structure and node contracts don't change, only the implementation behind each call | M |
| Expand language coverage toward more of the 22 scheduled Indian languages | Four languages proves the pattern works; broader coverage proves it scales | M |
| Add authentication and session persistence | Needed for anything beyond a single local demo session | M |
| Build a proper evaluation harness — WER per language, RAG faithfulness scoring, latency budget per turn, a guardrail red-team test set | Without this, every future change is a guess about whether it made things better or worse | L |

## Long-term / production roadmap

| Item | Why it matters | Effort |
|---|---|---|
| Real backend integration instead of the mocked rules-engine tool | The APY checker currently only implements rules in code; a production version needs to integrate with an actual eligibility/verification backend | L |
| Multi-user deployment with proper session isolation | Required before this could be used by more than one person at a time | L |
| Expand FAQ corpus coverage and set up a process to keep regulatory facts current | RBI/SEBI/IRDAI/PFRDA rules change often enough that a static 27-item dataset goes stale fast — needs an owner and a review cadence, not just more entries | L |
| Formal compliance review before treating any answer as authoritative financial/regulatory guidance | Legal/compliance sign-off is a hard prerequisite before this could be positioned as anything other than a demo | L |

## Explicitly out of scope

This stays a demo/informational tool. Even long-term, it will not:

- Give personalized financial advice.
- Execute real transactions (loan disbursal, scheme enrollment, payments, etc.).
- Replace a licensed financial advisor or a regulator's official guidance.
- Serve as a compliance system of record for any regulated entity.
